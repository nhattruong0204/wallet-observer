# WO-004 persistence acceptance

Issue [#4](https://github.com/nhattruong0204/wallet-observer/issues/4). Verified on
2026-10-05 in the pinned Linux devcontainer, Python 3.12.15 and PostgreSQL 16.15.
The isolated Compose project was `wallet-observer-wo004`; no provider probe,
Telegram send, purchase or production database change was involved.

## Delivered behavior

- Numbered, checksummed SQL migrations create canonical identity, source, event,
  execution, quote, checkpoint, work, notification and delivery storage.
- Database constraints preserve chain/address case, instruction identity and
  exact amounts; invalid fractional raw amounts are rejected rather than rounded.
- Source retries and equivalent canonical facts are idempotent. Corrections
  append immutable revisions and transactional publication intent.
- Source facts, work intent and checkpoint advances can commit together or roll
  back together. Stale checkpoint and event versions are rejected.
- A serialized dispatcher publishes only committed revisions with a safe replay
  cursor. Bounded pages advance from the last returned event, not the watermark.
- Durable jobs have expiring leases, ownership tokens, bounded attempts/retries,
  terminal failure and redacted error codes. Retention removes bounded batches
  of expired payloads while retaining deduplication identities.

The integration suite proves:

- Empty installation, v1-to-v2 upgrade preserving existing data, concurrent
  migration serialization, checksum mismatch rejection and transactional DDL
  rollback on an injected failure.
- Real buy-fixture replay creates one execution; actual stream/history overlap
  shares one source identity while retaining its two payload representations.
- Controlled distinct transaction/instruction identities with identical amounts
  remain distinct; they are storage tests, not invented provider captures.
- Transaction exceptions and forced producer connection termination leave no
  checkpoint advance, execution or phantom publication.
- A producer with a lower preallocated outbox ID can commit later and still be
  delivered after the earlier-committing producer. Concurrent dispatchers do not
  duplicate delivery; an injected delivery failure rolls back the cursor.
- A 78-digit raw integer and a long fractional USD value round-trip exactly;
  case-sensitive addresses and same-address tokens on different chains remain
  separate. Fractional, negative, nonfinite and oversized raw values are rejected.
- Immutable revisions retain original delivery snapshots through corrections;
  equivalent decimal encodings do not create additional revisions.
- Job claim contention, lost-lease fencing, retry exhaustion, final-attempt crash
  recovery, notification identity uniqueness and bounded payload expiry behave
  as specified.

## Reproduction

Inside the devcontainer, from the repository root:

```bash
make bootstrap
make doctor
make config-check
make migrate
make migrate
make lint
TEST_DATABASE_URL=postgresql://observer:observer-dev-only@db/wallet_observer make test
make fixtures
make build
```

The URL is the committed development-only default. Integration checks use random
schemas and remove only those schemas. Use a disposable database; never supply a
production URL. Without `TEST_DATABASE_URL`, ordinary Python tests skip the
PostgreSQL checks. `make test-integration` requires an explicit URL.

## Definition of done

- [x] Migrations apply to an empty database and an upgrade path is documented.
- [x] Duplicate fixture ingestion does not create extra executions.
- [x] Two distinct same-amount swaps remain distinct.
- [x] A rollback does not advance the safe source checkpoint or emit a phantom
      committed event.
- [x] Precision, address case and chain separation survive a database round-trip.
- [x] No user, billing, entitlement, quota or session tables are introduced.

## Limits

The storage DTO uses reviewed fixture facts; a production normalizer remains #7.
Collection, processing handlers, automatic dispatch/retention, watch APIs, live
browser replay and Telegram sending remain later issues. The foundation worker
still performs dependency checks only. Storage cannot establish upstream history
completeness or qualify a new chain/route. External side effects still require
idempotent handlers and explicit handling of uncertain acknowledgements.

Migrations are forward-only; destructive downgrade is unsupported. The
[data-model contract](../data-model.md) documents deliberate upgrade and backup
recovery. Current readiness checks connectivity, not schema version. Production
backup/restore automation is #17 and CI configuration is #15. Checks above ran
locally; no GitHub CI or deployment success is claimed. No application UI was
changed, so browser acceptance was not rerun for this issue. Mobile work remains
deferred under the website-first decision.
