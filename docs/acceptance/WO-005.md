# WO-005 acceptance evidence

Issue: [#5](https://github.com/nhattruong0204/wallet-observer/issues/5).
Date: 2026-10-06. Branch: `feat/wo005-watchlists`.
Implementation: [draft PR #43](https://github.com/nhattruong0204/wallet-observer/pull/43).
Status: implementation verified locally; initial private operator list pending.

The API implements watch CRUD, explicit monitoring state and collection intent,
groups, and versioned preview/apply/export using the existing PostgreSQL schema.
See [the contract](../watchlist-format.md). No provider collection, desktop
watchlist UI, product login, new dependency or migration is introduced.

## Definition-of-done evidence

| Requirement                                              | Evidence                                                                                                                                                                                                  |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Single/bulk API operations and clear errors              | HTTP integration tests cover CRUD, mixed per-row validation, stale preview revalidation, atomic rollback, commit failure, export/import, 404/409/415/422/503 and privacy.                                 |
| Duplicates do not create duplicate subscription intent   | Existing unique wallet/watch identities plus serialized writes; concurrent single and bulk additions leave one watch and one collection target. Actual provider subscriptions are #6 and remain disabled. |
| Pause changes collection intent and preserves history    | Active-to-paused and non-active states produce no target; removal hides the watch without deleting canonical history; explicit restore retains the ID.                                                    |
| Group rename/delete is specified and tested              | Names rename in place, conflicts return 409; deletion removes memberships only, retaining watches/history/state.                                                                                          |
| No login, quotas, public accounts or exclusive resources | Reuses existing personal tables and API; no new service, dependency, account schema or commercial limit. Batch bounds are documented resource limits.                                                     |

## Verification results

Verified in the repository's pinned devcontainer with PostgreSQL 16.15:

- `TEST_DATABASE_URL=postgresql://observer:observer-dev-only@db/wallet_observer make lint test fixtures build` passed: **138 Python tests** (92 non-database and 46 PostgreSQL integration checks), **4 frontend tests**, all seven real source-fixture checks, Ruff/formatting, ESLint/TypeScript, Prettier, frontend build and backend wheel/sdist build. No Python tests were skipped in this run.
- The added coverage comprises 31 input-contract checks and 22 real PostgreSQL HTTP integration checks, including 12 concurrent single/import requests, deferred commit failure, whole-batch rollback, mixed duplicate/invalid rows, export into an empty watchlist, a 25-row batch, group conflicts/deletion and retained history.
- A real Uvicorn process served HTTP preview/apply for 25 controlled address encodings, pause/remove/group rename/export and collection intent. After SIGTERM and a fresh API process, 25 watch records (one removed), the 24-row export and the controlled history marker were retained. Both processes emitted `service_stopped`; Uvicorn's documented re-raising of SIGTERM was treated as its expected signal exit, not an application failure. The disposable smoke schema was dropped afterward.
- The smoke process logs did not contain the private label/note probe strings. No operator data, provider calls or Telegram sends were used.
- All four watchlist modules were present in the built backend wheel. Existing migrations and dependency locks are unchanged.

Review was performed by the implementing agent using backend, database, AppSec
and complexity passes; no independent reviewer is claimed. The design keeps one
API, worker and PostgreSQL, reuses the current schema, and adds no dependency or
migration. Operator writes use a documented table-lock tradeoff appropriate to
this small single-operator scope; reads remain available. Browser E2E tests were
not run for this API-only change; existing frontend tests/build and static-serving
checks passed.
