The successful clean-clone check used `/home/truong/snap/docker/common/devcontainer-tmp/wallet-observer-wo001-clean` and the installed Docker/Compose binaries directly. This was a host path constraint; the repository configuration was not changed for it.

The clean-clone checks ran through the CLI's actual `up` and `exec` lifecycle. They did not launch a graphical VS Code session. Windows/WSL2 startup instructions were reviewed for the same Linux container flow; a separate Windows desktop was not manually tested. ARM64 images are pinned by the multi-platform indexes but were not executed here.

## Reproduction

On a host with ordinary Docker Engine and Node available, the equivalent lifecycle commands are:

```bash
git clone https://github.com/nhattruong0204/wallet-observer.git
cd wallet-observer
npx --yes @devcontainers/cli@0.89.0 up --workspace-folder .
npx --yes @devcontainers/cli@0.89.0 exec --workspace-folder . make doctor
npx --yes @devcontainers/cli@0.89.0 exec --workspace-folder . make lint
npx --yes @devcontainers/cli@0.89.0 exec --workspace-folder . make test
```

Before merge, check out the `issue-1-devcontainer` branch after cloning. See [development.md](../development.md) for the editor/terminal startup paths and database persistence commands.
