## Why we need this

The expanded release should have an honest feature/capability report and remain maintainable by one person.

## What to do

- Run a final desktop-browser website acceptance pass over all enabled personal features and publish a release/runbook update.
- Resolve or explicitly defer source-blocked capabilities without pretending they shipped.

## How to implement

1. Review every retained feature against the scope checklist; distinguish implemented, source-blocked, deliberately deferred, and excluded features.
2. Re-run meaningful correctness, correction, replay, notification, restore, and private-access checks across enabled adapters.
3. Measure 25–100 watched accounts only if actual usage justifies expansion; record provider costs, storage growth, lag, query performance, and gaps.
4. Document routine provider-key rotation, stopped-host recovery, data retention, backup restore, and monthly usage review.
5. Tag the release and link all completed issues and known limitations. No arbitrary algorithm is called an exact Wind reproduction.
