**Assessment:** [RayBot feasibility review](https://github.com/nhattruong0204/wallet-observer/blob/main/docs/raybot-integration-assessment.md).

## Why we need this

The existing RayBot watchlist can seed Wallet Observer without rebuilding it or changing the operator’s RayBot setup.

## What to do

- Extend the existing bulk-import workflow with a RayBot CSV format and an optional server-side read-only API import.
- Reuse aliases/groups from #5 and apply only reviewed changes; no continuous bidirectional synchronization.

## How to implement

1. Qualify the CSV header variants using an owner-supplied export or a vendor example. The documented export includes address, name, network, status and tag; balance and historical date columns are source annotations, not ledger facts. Never commit the personal export.
2. For API import, use the documented paginated wallet-list operation for explicitly selected destinations. A webhook destination uses its ID as user_id and bot 0. Ordinary bot destinations retain their selected bot number. Do not scan other users or assume all web-app fields are exposed by this API.
3. Share a bounded, redacting server-side API client with later RayBot work: throttle all public API operations together, handle 401/403/429 and truncated/repeating pagination, refuse redirects and redact credential-bearing query strings.
4. Preview new wallets, duplicate addresses, conflicting aliases, tags, skipped networks and source statuses before an atomic local apply. Preserve Solana case and deduplicate by chain/address across destinations. Default to preserving existing local labels and pause state.
5. Import only supported Solana watches; generic evm does not identify a chain. Report skipped/unsupported rows explicitly. Retain remote limit/pause/expired states as provenance, never silently activate every row. Missing labels/tags remain missing.
6. Keep remote state untouched: do not invoke add/delete/settings or create destinations as part of import. Imported names and tags are operator labels, not proof of identity or shared ownership.

## Definition of done

- [ ] CSV preview/apply and qualified API pagination reproduce the selected source list without leaking it.
- [ ] Repeated imports are idempotent, alias conflicts are visible, and partial downloads cannot remove local watches.
- [ ] Invalid, unsupported-chain, paused, duplicate and malicious CSV/text cases have meaningful tests.
- [ ] Existing watches and RayBot destinations remain unchanged unless explicitly selected local changes are applied.
