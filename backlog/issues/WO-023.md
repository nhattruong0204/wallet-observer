# [WO-023] Qualify FOMO identity, thesis, clan, and order data access

**Milestone:** Personal expansion

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

FOMO-specific behavior cannot be reconstructed solely from blockchain transactions. This gate prevents fake identity mappings or nonfunctional feature promises.

## What to do

- Identify a documented/authorized acquisition path for each needed FOMO capability.
- Produce a capability matrix and go/no-go decision before enabling dependent adapters.

## How to implement

1. Evaluate stable user IDs, wallet mappings, thesis IDs/text/token mentions, clan membership/size, and off-chain order state as separate capabilities.
2. Record source provenance, permission requirements, rate limits, historical coverage, monthly costs, replay/edit semantics, and representative sanitized payloads.
3. Verify an identity link against explicit source evidence; a similar name or shared funding is not enough.
4. Document unsupported data as blocked. Keep manual wallet labels and wallet-only monitoring available.
5. Do not scrape private endpoints without access, bypass sign-in, reuse Wind's backend, or assume a trading SDK exposes social metadata.
