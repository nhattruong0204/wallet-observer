# [WO-033] Show qualified RayBot metadata and position observations on the website

<!-- wallet-observer-task:WO-033 -->

**Milestone:** Optional RayBot

**Status:** Planned; enable only after the required RayBot capability passes qualification. Optional to first-live delivery.

**Website first:** Desktop-browser website and supporting services only. Native mobile, installable PWA, device push and mobile acceptance remain deferred. Monitoring is read-only; no execution, signing keys, new chains or subscription upgrades are authorized.

**Assessment:** [RayBot feasibility review](https://github.com/nhattruong0204/wallet-observer/blob/main/docs/raybot-integration-assessment.md).

## Why we need this

RayBot can add context already available in webhook payloads, but its reported prices and positions have different provenance from our observed ledger.

## What to do

- Add optional RayBot metadata and position panels to existing wallet/token views after their individual qualification gates pass.
- Preserve the local observed-position computation and existing market-data selection rules.

## How to implement

1. Store source, receipt time, source timestamp where defined, currency, coverage and qualification version for each observation. Do not assume token.created is on-chain mint creation, receipt time is quote time, or a missing value is zero.
2. Use the existing metadata/quote cache with explicit freshness and conflict policy. RayBot payload prices are event-associated observations; they do not establish a streaming quote service or historical pricing API. Never choose a price merely because its webhook arrived last.
3. Treat RayBot position fields as source-reported snapshots. The payload examples describe native-currency positions while UI settings can show USD: qualify actual units and fee basis before displaying totals. If units or association to a wallet/token are missing, keep the value unavailable.
4. Handle pre-existing holdings, missing cost basis, transfers, corrections and partial history. Preserve negative PnL and nulls in a suitable signed observation model rather than forcing them into nonnegative execution amount fields. A first-buy flag does not prove complete lifetime history.
5. Display source/freshness/coverage next to qualified values and keep them separate from locally reconstructed PnL. Sanitize token names/links; disable fields when the capability loses qualification. No social-feed ingestion, new chains or external image fetches without the existing policy.
