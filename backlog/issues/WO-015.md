# [WO-015] Add CI and meaningful fixture-based regression gates

<!-- wallet-observer-task:WO-015 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

Fast AI-assisted iteration needs executable checks for data correctness and recovery, without making every CI run dependent on paid providers.

## What to do

- Set up GitHub Actions for Python/TypeScript checks, builds, migrations, and targeted integration tests.
- Make later feature PRs extend the fixture suite as their behavior is implemented.

## How to implement

1. Run formatting/linting, type checks where configured, unit tests, PostgreSQL integration tests, and frontend production build.
2. Use sanitized fixtures and deterministic time for normalization, deduplication, quote ordering, replay, and notification retry tests.
3. Start with minimal working gates and extend them in WO-007 through WO-014. Do not wait for all later work to create CI.
4. Keep external live probes manual/opt-in with explicit budget limits. Never expose provider credentials to untrusted pull requests.
5. Add a PR checklist describing the issue, behavior, verification evidence, migrations, and known limitations.

## Definition of done

- [ ] A clean CI run passes without private keys, provider accounts, or Telegram access.
- [ ] A deliberate supported-trade regression and a duplicate/replay regression fail the appropriate tests.
- [ ] Database migrations are exercised on disposable PostgreSQL.
- [ ] Frontend builds and representative browser flows are checked.
- [ ] Workflow permissions are minimal and failed checks are not hidden by unconditional success.
