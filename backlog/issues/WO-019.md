# [WO-019] Add observed positions and first/add/re-entry/exit semantics

<!-- wallet-observer-task:WO-019 -->

**Milestone:** Personal expansion

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

Position context makes wallet activity easier to understand, but incomplete history must not produce false first-buy, exit, or P&L claims.

## What to do

- Build a per-wallet/token observed quantity ledger with explicit opening-balance provenance and coverage.
- Derive first observed buy, add, re-entry, trim, and exit only when available evidence supports them.

## How to implement

1. Choose a reproducible ledger order using chain facts and stable tie-breakers. Preserve adjustments and corrections rather than rewriting unknown history.
2. Handle transfers, missing opening balances, unsupported routes, token-decimal changes, and partial backfill by downgrading completeness.
3. Separate observed quantity, current market value, executed amounts, and realized P&L. Do not introduce accounting-grade P&L in this task.
4. Implement sell-share only when the prior quantity is known; mark unknown instead of dividing by an invented balance.
5. Rebuild a sample ledger from stored executions and compare it with incremental processing.

## Definition of done

- [ ] An unknown opening balance produces partial/unknown position labels.
- [ ] First buy is labelled first observed unless prior-history completeness is demonstrated.
- [ ] Transfer-in/out and failed/refunded/corrected events do not masquerade as profitable executions.
- [ ] Full exit requires supported evidence of the remaining balance.
- [ ] Incremental and replayed ledgers agree on representative fixtures.
- [ ] The UI exposes the coverage and estimation method.
