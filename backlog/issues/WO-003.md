## Why we need this

One codebase with explicit service boundaries keeps a personal deployment manageable while allowing collection to run independently of browser requests.

## What to do

- Create a Python backend package with API and worker entrypoints, plus a React/TypeScript frontend.
- Define typed settings, health endpoints, structured logs, dependency locks, and a local development command surface.

## How to implement

1. Use FastAPI for HTTP/WebSocket, an asynchronous worker process, and a conventional React build. Avoid microservices or a mandatory Redis dependency.
2. Validate configuration on startup. Distinguish required database configuration from optional provider/Telegram credentials and enabled feature flags.
3. Provide liveness and readiness endpoints; readiness should reflect the service's actual dependencies. Serve a minimal frontend with explicit empty and offline states.
4. Keep any commands added to README executable. Provide a fixture mode so ordinary development and CI do not require external API calls.
