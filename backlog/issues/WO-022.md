## Why we need this

Personal convenience should not require the account, subscription, and multi-device synchronization systems removed from scope.

## What to do

- Provide single-user filter and threshold settings, saved views, pins/ignore with undo, and configuration export/import.
- Support useful desktop website display preferences without reproducing the commercial workspace or adding mobile-device settings.

## How to implement

1. Version the configuration schema and separate server settings from browser-local presentation choices.
2. Export watches, aliases, groups, settings, and signal definitions; exclude credentials, device secrets, and private source payloads.
3. Preview imports with duplicate/conflict decisions, validate references, and apply changes transactionally where practical.
4. Implement saved account/group/chain filters and bounded pin/ignore state. Preserve reading continuity across view changes.
5. Treat drag/resize layouts and additional language/theme variants as optional follow-up refinements; do not block the personal acceptance gate on them.

## Definition of done

- [ ] A configuration export/import round-trip preserves non-secret settings.
- [ ] Exports contain no bot token, provider key, or infrastructure credential.
- [ ] Invalid imports report specific errors without corrupting the existing configuration.
- [ ] Saved views use the same backend filter semantics as the feed.
- [ ] Ignore has an undo path and pins have an explicit retention policy.
- [ ] No login, cross-user settings merge, or membership logic is introduced.
