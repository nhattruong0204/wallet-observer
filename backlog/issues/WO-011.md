## Why we need this

Network changes and browser suspension must not create missing cards, duplicate rows, or stale event states.

## What to do

- Add WebSocket delivery of new events, revisions, source status, and reconnect catch-up.
- Use the committed dispatch log as the live cursor and define its retention behavior.

## How to implement

1. Assign delivery positions through one transactionally ordered dispatcher after canonical commits; use the outbox to bridge API/worker failures.
2. Define hello/cursor, event, event_update, status, heartbeat, resync-required, and error messages with versioned schemas.
3. Coordinate catch-up and live attachment around a committed watermark. Resume without a race between the history response and live stream.
4. If a cursor predates retained delivery history, request a bounded resnapshot and show that transition; do not silently claim full recovery.
5. Bound client buffers and apply backpressure/disconnect behavior. Browser reconnects use jitter and do not retrigger old notifications.

## Definition of done

- [ ] Disconnecting while new events arrive restores all retained events once.
- [ ] An update modifies the existing card identity rather than inserting a duplicate.
- [ ] Out-of-order source timestamps do not break the delivery cursor.
- [ ] Expired cursors produce an explicit resync path.
- [ ] A concurrent-commit regression demonstrates that the watermark cannot skip a later commit with an earlier allocated database ID.
