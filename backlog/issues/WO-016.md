# [WO-016] Expose source health, usage budgets, and retention controls

<!-- wallet-observer-task:WO-016 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

A low-cost personal system must show when its data is stale or its provider/storage usage is growing unexpectedly.

## What to do

- Add health/status APIs and a compact dashboard status view.
- Track collection lag, recovery gaps, queue age, provider requests/credits where available, and retention jobs.

## How to implement

1. Separate source occurrence-to-ingestion lag from browser RTT and API query time. Record unknown timing rather than manufacturing a latency number.
2. Show last successful source contact, watched-wallet count, parser errors, oldest queued job, notification failures, and history coverage.
3. Add monthly usage settings and application-side thresholds for optional backfill/quote work. Do not claim these settings are an absolute vendor spending cap.
4. Implement bounded deletion/compaction for raw payloads and delivery history; preserve deduplication and declared coverage semantics.
5. Document baseline server disk/RAM and provider usage from the pilot, plus alerts for stopped collection and a full disk.

## Definition of done

- [ ] Disconnecting the source produces a visible stale/degraded state.
- [ ] Budget thresholds stop or reduce optional work while preserving recorded gaps.
- [ ] Retention does not break live replay silently; expired cursors request resync.
- [ ] A small metrics/status page answers whether collection and delivery are healthy.
- [ ] Storage growth and measured usage are recorded in the pilot report.
