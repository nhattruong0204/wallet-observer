## Why we need this

A tracker that loses activity whenever the VPS or provider disconnects cannot support dependable histories or signals.

## What to do

- Recover missed source activity using persisted checkpoints and the qualified history endpoint.
- Separate live delivery from historical replay and expose unrecoverable coverage gaps.

## How to implement

1. Persist a per-source/per-watch recovery boundary supported by the provider. Use an overlap window and stable deduplication rather than assuming a perfect replay cursor.
2. Process backfill through the same normalization code as live events, tagged with replay provenance and alert eligibility.
3. Bound backfill depth, page count, concurrency, and credits. Persist job progress and retry leases so interruption is resumable.
4. Define the source-history limit and record a gap if it prevents complete recovery. Never advance a checkpoint over failed unpersisted work.
5. Maintain event occurrence order separately from the ordered delivery log; late source events are valid.

## Definition of done

- [ ] An outage-and-restart exercise recovers known missing fixtures without duplicates.
- [ ] Live ingestion can continue while a bounded backfill runs.
- [ ] Historical imports do not flood Telegram.
- [ ] A second interruption resumes rather than restarting an unlimited scan.
- [ ] Coverage gaps are returned by the API and visible to the user.
- [ ] A database transaction rollback does not falsely move the recovery boundary.
