# [WO-001] Create the devcontainer and reproducible development toolchain

<!-- wallet-observer-task:WO-001 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

A consistent environment lets you and Astra reproduce the same install, database connection, lint results, and debugging behavior across Windows/WSL and Linux.

## What to do

- Create a devcontainer with Python, Node, Git, PostgreSQL client tools, and a non-root development user.
- Define a development Compose setup and documented task commands; keep production configuration separate.

## How to implement

1. Use a supported Python release and Node LTS; pin the chosen versions and lock dependency resolutions. Record selections in docs/development.md.
2. Configure .devcontainer/devcontainer.json, a development Dockerfile, and a PostgreSQL service with a named volume and healthcheck. Forward only development ports.
3. Install dependencies through uv and the selected JavaScript package manager. Add Python/TypeScript formatting, linting, and editor debug configurations.
4. Provide placeholder environment variables and an explicit setup command. Do not put API keys or personal watchlists in images, tracked files, or lifecycle-hook output.

## Expected files and deliverables

- `.devcontainer/devcontainer.json`
- `.devcontainer/Dockerfile`
- `compose.dev.yml`
- `.env.example`
- `docs/development.md`

## Dependencies

None. Start here.

## Definition of done

- [x] A clean clone opens in the devcontainer and the non-root user can edit files.
- [x] Python, Node, package managers, and PostgreSQL client versions are documented and reproducible.
- [x] The database healthcheck succeeds and survives a container restart.
- [x] Setup commands succeed without paid credentials; provider-dependent commands report what is missing.
- [x] Documented Windows/WSL and Linux startup instructions contain no unimplemented success claims.
