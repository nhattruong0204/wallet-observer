# [WO-010] Build feed, history, wallet/token queries, and search APIs

<!-- wallet-observer-task:WO-010 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

One consistent read contract keeps feed, detail pages, and future analytics aligned and prevents duplicated business rules in the frontend.

## What to do

- Expose read APIs for event history, wallets, tokens, source health, and exact/alias search.
- Implement cursor pagination and personal filters without entitlement gates.

## How to implement

1. Define response DTOs for event revision, chain, wallet, token, status, quantities, valuation provenance, and coverage.
2. Use stable composite ordering for history pagination; specify occurrence-time versus delivery-time views and late-event behavior.
3. Implement wallet/group, token, direction, amount, time-window, and supported-state filters with indexed SQL.
4. Use exact address/signature lookup before text search. Limit result sizes and return useful invalid-cursor errors.
5. Document endpoints in generated OpenAPI plus short request/response examples; keep raw credentials and excessive provider payloads out of responses.
