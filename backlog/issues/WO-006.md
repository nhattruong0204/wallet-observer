# [WO-006] Build the provider adapter and live collection worker

<!-- wallet-observer-task:WO-006 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

Always-on ingestion is the source of the live feed. The browser must not be responsible for keeping collection running.

## What to do

- Implement the qualified outbound stream adapter and persist raw source events.
- Manage watch-filter changes, reconnect/backoff, bounded processing, and source health.

## How to implement

1. Hide provider payloads behind a small adapter interface: capabilities, subscription updates, event envelope, history lookup, and health.
2. Prefer the qualified outbound WebSocket path so the private dashboard needs no public webhook endpoint. If an approved provider requires callbacks, expose only a separately authenticated ingestion route.
3. Persist accepted source records and durable processing work before advancing a safe source checkpoint.
4. Handle disconnects, subscription rejection, rate limiting, malformed payloads, and provider-schema changes. Quarantine unrecognized payloads instead of discarding them silently.
5. Bound queues and retries. On watch changes, avoid overlapping subscriptions causing unbounded duplicate delivery.

## Definition of done

- [ ] A real qualified wallet produces persisted source events without an open browser.
- [ ] Duplicate source notifications are harmless.
- [ ] A restart restores watch intent and initiates gap recovery.
- [ ] Rate-limit responses trigger backoff and a visible degraded state.
- [ ] Captured sensitive query parameters are redacted from logs.
- [ ] No trade-signing, execution, or private-key handling code exists.
