# [WO-017] Prepare private VPS deployment, backups, and rollback

<!-- wallet-observer-task:WO-017 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

The first live release needs an always-on deployment that can restart and recover without exposing a personal control panel.

## What to do

- Create a small production Compose deployment for API/frontend, worker, and PostgreSQL.
- Document private access, secret provisioning, restart behavior, backup/restore, and version rollback.

## How to implement

1. Use reproducible container builds and explicit image/version tags. Build frontend assets in a build stage and serve them through the application or a small proxy.
2. Bind the dashboard to loopback/private networking and use an existing trusted tunnel/VPN or SSH forwarding. Do not add a product login system or publish PostgreSQL.
3. Provision only the selected provider and Telegram credentials on the host; do not place them in GitHub issues, image layers, or logs.
4. Back up PostgreSQL plus non-secret configuration to an off-machine destination. Write restore and collector-resume steps that preserve delivery state.
5. Run migrations as a deliberate deployment step. Document schema-compatible rollback and a restore path when a migration cannot be rolled back safely.

- [ ] The documented deployment works on the selected VPS and restarts after a reboot.
- [ ] An unauthorized public request cannot reach control APIs or the database.
- [ ] One backup is restored into a separate disposable database and verified.
- [ ] A restored worker resumes without historical alert flooding.
- [ ] Release version, deploy procedure, rollback procedure, and expected monthly infrastructure cost are documented.
