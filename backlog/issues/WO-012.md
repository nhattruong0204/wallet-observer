# [WO-012] Build the responsive live feed and watchlist interface

<!-- wallet-observer-task:WO-012 -->

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

## Why we need this

The first release should let you follow activity in one place without the complexity of Wind's commercial workspace.

## What to do

- Build fixed Feed, Watchlist, and Settings navigation with responsive trade cards.
- Add watch editing, filters, connection/coverage states, and stable reading behavior.

## How to implement

1. Use reusable typed components and a small state layer. Render the API's data rather than recomputing trade semantics in the browser.
2. Implement a virtualized or otherwise bounded feed, cursor loading, a new-event counter, and jump-to-latest while preserving the user's scroll position.
3. Support copy wallet/token address, explorer links, group/direction/amount filters, and visible unknown/stale fields.
4. Provide accessible controls, keyboard focus, mobile-width layouts, and explicit loading, empty, partial, offline, and error states.
5. Use original styling and assets. No audio, account login, Pro upsell, or drag/resize workspace is required.

## Definition of done

- [ ] A real subscribed event appears, updates in place, and remains in history after reload.
- [ ] Adding/pausing a wallet changes the backend watch state and shows the result.
- [ ] New events do not repeatedly pull the reader away from older cards.
- [ ] Core flows work at desktop and approximately 390px mobile width.
- [ ] No source keys or Telegram token appear in the browser bundle or network responses.
