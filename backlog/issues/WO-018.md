# [WO-018] Validate real traffic and release the first website beta

**Milestone:** First live

**Plan:** [BUILD_PLAN.md](https://github.com/nhattruong0204/wallet-observer/blob/main/BUILD_PLAN.md)

**Website first (2026-10-05):** Deliver the desktop-browser website and its supporting services. Native mobile apps, installable PWA features, device push, mobile-specific UX and mobile acceptance gates are deferred. Existing responsive behavior may remain. See the [scope decision](https://github.com/nhattruong0204/wallet-observer/blob/main/docs/decisions/0003-website-first.md).

## Why we need this

The first-live milestone should be based on observed operation and correctness, not only a successful build or a screenshot.

## What to do

- Run the deployed tool with 10–25 selected wallets and publish a concise acceptance report.
- Release a tagged first website beta after the desktop-browser launch gate passes; keep unsupported features visibly disabled.

## How to implement

1. Observe at least 24 hours of operation, extending the interval if insufficient representative activity occurs. Record event counts, source coverage, errors, lag, and provider usage.
2. Verify a sample of supported buys/sells against source transactions. Use recorded fixtures for edge cases not observed during the trial.
3. Exercise source disconnect, worker restart, browser reconnect, provider throttling, quote outage, duplicate delivery, and backup restore.
4. Confirm private access and inspect frontend artifacts/logs for accidental credentials. Review notification volume with the user.
5. Document limitations and remaining defects; do not mark partial-history positions, FOMO metadata, or unsupported routes complete. Record mobile apps and mobile-specific acceptance as deferred; they do not block the website release.

## Definition of done

- [ ] All first-live dependencies are complete and CI passes.
- [ ] Website feed, history, watch management and details work with real data in a desktop browser, and server-side Telegram alerts work.
- [ ] Critical duplicate, missing-event recovery, and transfer-as-buy defects are resolved.
